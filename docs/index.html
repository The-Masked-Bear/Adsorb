Why allocate gigabytes of virtual memory and burn 15 Watts on a Raspberry Pi or Docker container just to discard 40-byte UDP datagrams? Hardware Architecture

SILICON EXECUTION SCHEMATIC

How dual Xtensa LX7 cores and 8MB Octal SPI PSRAM eliminate operating system overhead.

CORE 1 — REAL-TIME ISOLATION PRIORITY 5 RTOS TASK

DEDICATED UDP 53 ENGINE

Core 1 executes an uninterruptible low-latency loop. When a UDP query arrives on port 53, Core 1 parses the RFC 1035 labels directly into a stack buffer, evaluates the 64-bit FNV-1a hash, and searches the sorted 8MB Octal PSRAM vector via binary search.

Execution Frequency: 240 MHz (Zero Throttling)
Dynamic Heap Allocation: 0 Bytes (Fixed Buffers)
DoH Canary Traps: use-application-dns.net
LATENCY TARGET: < 1.0ms 100% HARDWARE-DRIVEN
CORE 0 — SYSTEM & TELEMETRY PRIORITY 1 RTOS TASK

MANAGEMENT & WEB ENGINE

Core 0 manages asynchronous Wi-Fi reconnects, LittleFS flash memory operations, REST API serialization, and serves the neo-brutalist status dashboard on port 80. Network activity on Core 0 never stalls Core 1's real-time DNS loop.
